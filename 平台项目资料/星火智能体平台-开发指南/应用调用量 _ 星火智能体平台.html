接口说明 ​

本文档是介绍通过两种方式调用星火API以及智能体，任务链的会话chat接口
一种是SDK的方式，一种是通过okhttp的方式，支持Java和Python语言，具体调用示例代码工程请看 应用管理 -> 协议 -> 调用示例

1. 请求地址 ​

请求地址根据平台部署的后访问地址来确定

  • 平台部署使用的是域名进行访问，如https://xxx.xxx.xxx，则会话的地址也是使用这个
  • 平台部署使用的是IP+端口进行访问，如http://xxx.xxx.xxx.xxx:30009，则会话的地址也是使用IP+端口的地址

2. 接口鉴权 ​

  • java请参考示例代码中**AuthUtils**
  • python请参考示例代码中**create_url**函数
  • 其他语言参考下面说明

2.2 鉴权参数： ​

参数名称类型
必传
参数要求
参数说明
hoststring是xxx.xxx.xxx.xxx或www.xxx.com请求主机
datestring是RFC1123格式，如Thu, 01 Aug 2019 01:53:21 GMT当前时间戳
authorizationstring是参考下方authorization参数生成规则使用base64编码的签名相关信息(签名基于hmac-sha256计算)
assistantCodestring是在平台->应用详情->关联智能体编码应用关联智能体编码

date参数生成规则：

  1. date必须是UTC+0或GMT时区，RFC1123格式(Thu, 01 Aug 2019 01:53:21 GMT)。
  2. 服务端会对Date进行时钟偏移检查，最大允许300秒的偏差，超出偏差的请求都将被拒绝。**

authorization参数生成规则：

  1. 获取接口密钥APIKey 和 APISecret。 在智能体平台应用管理，创建应用关联智能体后后即可查看，均为32位字符串。
  2. 参数authorization base64编码前（authorization_origin）的格式如下。
shell
api_key="$api_key",algorithm="hmac-sha256",headers="host date request-line",signature="$signature"
1

其中 api_key 是在控制台获取的APIKey，algorithm 是加密算法（仅支持hmac-sha256），headers 是参与签名的参数（见下方注释）。 signature 是使用加密算法对参与签名的参数签名后并使用base64编码的字符串，详见下方。

注： headers是参与签名的参数，请注意是固定的参数名（"host date request-line"），而非这些参数的值。

  1. signature的原始字段(signature_origin)规则如下。

signature原始字段由 host，date，request-line三个参数按照格式拼接成， 拼接的格式为(\n为换行符,’:’后面有一个空格)：

shell
host: $host\ndate: $date\n$request-line
1

text

date = Thu, 01 Aug 2019 01:53:21 GMT

shell

  1. 使用hmac-sha256算法结合apiSecret对signature_origin签名，获得签名后的摘要signature_sha。
shell
signature_sha=hmac-sha256(signature_origin,$apiSecret)
1

其中 apiSecret 是在控制台获取的APISecret

  1. 使用base64编码对signature_sha进行编码获得最终的signature。
shell
signature=base64(signature_sha)
1

假设

shell

  1. 根据以上信息拼接authorization

base64编码前（authorization_origin）的字符串，示例如下。

shell
api_key="keyxxxxxxxx8ee279348519exxxxxxxx", algorithm="hmac-sha256", headers="host date request-line", signature="sTmo4hl0LvdKY4KF9mpbJWHmDQs4/1gfOuH0fpYmWgo="
1

注： headers是参与签名的参数，请注意是固定的参数名（"host date request-line"），而非这些参数的值。

  1. 最后再对authorization_origin进行base64编码获得最终的authorization参数。
shell

2.3 鉴权url示例(golang) ​

go
//@hosturl :  like  ws://xxx.xxx.xxx.xxx:30009/openapi/flames/v2/chat
//@apikey : apiKey
//@apiSecret : apiSecret
func assembleAuthUrl(hosturl string, apiKey, apiSecret string, bodyId string) string {
   ul, err := url.Parse(hosturl)
   if err != nil {
      fmt.Println(err)
   }
   //签名时间
   date := time.Now().UTC().Format(time.RFC1123)
   //参与签名的字段 host ,date, request-line
   signString := []string{"host: " + ul.Host, "date: " + date, "GET " + ul.Path + " HTTP/1.1"}
   //拼接签名字符串
   sgin := strings.Join(signString, "\n")
   //签名结果
   sha := HmacWithShaTobase64("hmac-sha256", sgin, apiSecret)
   //构建请求参数 此时不需要urlencoding
   authUrl := fmt.Sprintf("api_key=\"%s\",algorithm=\"%s\", headers=\"%s\", signature=\"%s\"", apiKey,
   "hmac-sha256", "host date request-line", sha)
   //将请求参数使用base64编码
   authorization:= base64.StdEncoding.EncodeToString([]byte(authUrl))
   v := url.Values{}
   v.Add("host", ul.Host)
   v.Add("date", date)
   v.Add("authorization", authorization)
   v.Add("bodyId", bodyId)
   //将编码后的字符串url encode后添加到url后面
   callurl := hosturl + "?" + v.Encode()
   return callurl
}

2.4 鉴权结果 ​

如果握手成功，会返回HTTP 101状态码，表示协议升级成功；如果握手失败，则根据不同错误类型返回不同HTTP Code状态码，同时携带错误描述信息，详细错误说明如下：

错误编码
说明
错误描述信息
解决方法
401缺少authorization参数“{message”:”Unauthorized”} 检查是否有authorization参数，详情见authorization参数详细生成规则
401签名参数解析失败“{message”:”HMAC signature cannot be verified”}检查签名的各个参数是否有缺失是否正确，特别确认下复制的api_key是否正确
401签名校验失败{“message”:”HMAC signature does not match”}签名验证失败，可能原因有很多。
1. 检查api_key,api_secret 是否正确。
2.检查计算签名的参数host，date，request-line是否按照协议要求拼接。
3. 检查signature签名的base64长度是否正常(正常44个字节)。
403时钟偏移校验失败“{message”:”HMAC signature cannot be verified, a valid date or x-date header is required for HMAC Authentication”}检查服务器时间是否标准，相差5分钟以上会报此错误
403IP白名单校验失败"{message":"Your IP address is not allowed"}可在控制台关闭IP白名单，或者检查IP白名单设置的IP地址是否为本机外网IP地址
